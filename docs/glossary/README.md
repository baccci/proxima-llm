# Glossary and explanation style

This folder holds [glossary.md](glossary.md), a running dictionary of the technical terms these docs
use, each with a plain definition and a real example from this app. This README describes the
explanation style the glossary and the wider docs follow, so the writing stays readable to someone
who is strong on app architecture but newer to some of the jargon.

## The style these docs follow

1. Define a term the first time it appears, right where it appears. After that, use it freely.
2. One idea per sentence. Keep sentences short.
3. No stacked parentheses or dashes. If a point matters, give it its own sentence. If it doesn't, cut it.
4. Walk to the conclusion. Don't drop it as shorthand and assume the reader fills the gap.
5. Never lean on a shorthand without saying what it means, or linking it.
6. Short paragraphs, natural everyday English, with flow. Technical terms only when they earn their place.
7. Every new term goes into glossary.md.

## How the glossary grows

When these docs introduce a term a reader might not know, it gets an entry here. The file is meant to
be read at any time to refresh a definition. If an entry is still unclear, that is a signal to rewrite
it simpler, not to expect the reader to work harder.
