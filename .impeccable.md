# Impeccable

Design guidelines for Proxima. This file is the persistent design brief —
consult it before any UI/UX work.

## Design Context

### Users

Developers and power users who live in LLMs daily — coding, research, drafting.
They reach for this app expecting **speed, keyboard control, and information
density**. They know the domain; they don't need hand-holding, they need the
tool to keep up with them. Mouse-optional: power users navigate by keyboard.

### Brand Personality

**Premium · crafted · precise.** The app should feel like a high-end native Mac
application where every detail is intentional — not a generic web chat wrapper.
Voice is confident and quiet: it earns trust through polish and restraint, not
decoration. Three words: *considered, sharp, native.*

Emotional goal: the user should feel they're holding a finely-made instrument —
quiet confidence, zero friction, nothing arbitrary.

### Aesthetic Direction

Dark-first (the app boots `.dark`; the Figma source is dark). The visual system
is already established in [global.css](src/mainview/global.css):

- **Accent**: periwinkle blue `#7C9CFF` (`--color-accent-500`), used sparingly.
- **Neutrals**: slightly cool ramp; dark surfaces `#0e0e10 → #202024`.
- **Type**: Geist (sans), Geist Mono (code).
- **Native chrome**: real macOS traffic-light window controls (native/), drag
  regions, thin theme-aware scrollbars.

Direction for new UI = **native Mac fidelity × dense utilitarian**. Mimic macOS
conventions (system feel, native chrome, familiar interaction patterns) while
favoring compact, information-dense layouts over generous whitespace — closer to
Linear / Raycast efficiency than a spacious marketing site. Accent is a seasoning,
not the main course: lean on the neutral ramp, deploy periwinkle for focus/action
moments.

**Anti-references**: generic AI-chat web UIs, bubbly consumer apps, heavy
gradients/glassmorphism for its own sake, whitespace-heavy landing-page aesthetics.

### Accessibility

- **WCAG AA contrast** in both light and dark themes — verify text and UI
  element contrast when adding/altering tokens or surfaces.
- **Full keyboard navigation**: everything reachable and operable without a
  mouse; visible focus rings (`--ring`); honor the no-`useEffect` / hotkeys-js
  patterns already in use.
- Beyond AA contrast + keyboard nav, no formal compliance bar — apply sensible
  defaults (e.g. respect `prefers-reduced-motion` where motion is non-essential).

### Design Principles

1. **Native over novel** — match macOS conventions and the existing token system
   before inventing new patterns. Consistency reads as craft.
2. **Density with hierarchy** — pack information, but earn it with clear visual
   hierarchy; compact must never mean cluttered.
3. **Accent as punctuation** — neutrals carry the UI; periwinkle marks focus,
   selection, and primary action only.
4. **Keyboard-first** — every action has a path without the mouse; focus states
   are designed, not default.
5. **Detail is the product** — spacing, alignment, motion, and contrast are
   intentional everywhere. If it looks arbitrary, it's a bug.
